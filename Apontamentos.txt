Sim. O **MiniRT** é um dos projetos mais famosos da 42, e talvez um dos que mais fazem os alunos mudarem a forma de pensar sobre programação. Até esse momento, muitos projetos da 42 focam em algoritmos, parsing e estruturas de dados. O MiniRT introduz um assunto completamente diferente: **Computação Gráfica (Computer Graphics)**.

A melhor forma de entender o projeto é pensar nele da seguinte maneira:

> **O MiniRT é um programa que simula como a luz interage com objetos 3D para gerar uma imagem 2D.**

Ou seja, vocês vão criar um **ray tracer**, um programa que desenha uma cena lançando milhões de raios imaginários.

# O que é um Ray Tracer?

Imagine que você está olhando para uma cena.

Normalmente pensamos:

> "A luz sai do Sol e chega aos nossos olhos."

Mas isso seria extremamente caro de simular.

Então o ray tracing faz o contrário.

Ele pergunta:

> "Para cada pixel da tela, o que meu olho está vendo?"

Então:

```
Olho (Camera)
      |
      |
      |
      V
 ----------------------
|                      |
|      Tela            |
|   (Viewport)         |
|                      |
 ----------------------
        |
        |
        V
     Raio
        |
        |
        |
        V
      Cena
```

Para cada pixel:

```
Pixel (120,40)

↓

Criar um raio

↓

O raio bate em alguma coisa?

↓

SIM

↓

Qual objeto?

↓

Qual cor?

↓

Desenhar pixel
```

Repete isso para TODOS os pixels.

Se a imagem for

```
800 x 600
```

Serão

```
480.000 raios
```

Cada um sendo calculado independentemente.

Esse é literalmente o projeto.

# O pipeline completo do MiniRT

O projeto inteiro pode ser resumido assim:

```
Ler arquivo .rt

↓

Guardar objetos

↓

Criar câmera

↓

Para cada pixel

↓

Gerar raio

↓

Encontrar objeto atingido

↓

Calcular iluminação

↓

Colorir pixel

↓

Enviar imagem para MiniLibX
```

Se você entender esse fluxo, já entendeu 70% do projeto.

Sem vetores você não faz MiniRT.


### Soma

```

```

### Subtração

```

```

### Multiplicação por escalar

```
A * t
```

### Comprimento

```
|A|
```

### Normalização

Transformar

```

```

em

```
vetor de comprimento 1
```

---

### Produto Escalar (Dot Product)

Esse é o rei do MiniRT.

```
A • B
```

Serve para descobrir

* ângulo
* iluminação
* reflexão
* câmera
* interseções

Tudo usa dot product.

Estudem MUITO isso.

---

### Produto Vetorial

```
A × B
```

Serve para criar bases da câmera.

# O maior erro que quase todos os grupos cometem

Muitos começam tentando implementar o projeto inteiro ao mesmo tempo:

* parser
* esfera
* plano
* cilindro
* luz
* câmera
* MiniLibX

Resultado: o projeto parece enorme e difícil de depurar.

Em vez disso, construam uma cadeia de funcionalidades que sempre produza algo visível:

1. Mostrar uma janela.
2. Desenhar um pixel.
3. Desenhar um fundo.
4. Lançar um raio por pixel.
5. Detectar a interseção com **uma única esfera**.
6. Pintar a esfera.
7. Adicionar iluminação.
8. Adicionar os demais objetos.

Assim, a cada etapa vocês terão um programa funcional e será muito mais fácil localizar erros.

## Minha sugestão de plano de estudos (2 semanas)

Se vocês estudarem cerca de 2 a 3 horas por dia:

* **Dias 1–2:** Vetores, produto escalar, produto vetorial, normalização.
* **Dias 3–4:** Raios, geometria analítica e interseção raio-esfera.
* **Dias 5–6:** Câmera, viewport e geração de raios para cada pixel.
* **Dias 7–8:** Iluminação difusa (Lambert) e normais.
* **Dias 9–10:** Planos e cilindros.
* **Dias 11–12:** Sombras e múltiplos objetos.
* **Dias 13–14:** Parsing do `.rt`, integração com a MiniLibX e organização do código.

---

Eu também recomendaria encarar o MiniRT como um pequeno motor gráfico. Em vez de pensar "preciso fazer um projeto da 42", pense que vocês estão construindo, passo a passo, um programa composto por cinco subsistemas:

* **Matemática:** vetores, raios e interseções.
* **Cena:** parser e estruturas dos objetos.
* **Renderização:** percorre cada pixel e lança os raios.
* **Iluminação:** calcula cor, intensidade e sombras.
* **Exibição:** envia a imagem final para a MiniLibX.

Essa separação mental ajuda muito na implementação e facilita a divisão do trabalho entre os membros da equipe. Quando cada módulo funciona isoladamente, a integração final tende a ser bem mais tranquila.
